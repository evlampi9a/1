# Задача: разметка исторических промптов креаторов по бакетам S01–S20 моделью Jev

## Контекст

Креаторы на платформе генерируют контент по текстовым промптам. Промпты, накопленные за всё время работы платформы, никогда не размечались по единой политике контента. Поэтому мы не знаем:

- какая доля генераций приходится на допустимый взрослый контент, а какая — на запрещённый;
- какие креаторы систематически генерируют контент из красных бакетов;
- на каких данных строить правила модерации и в будущем проверять промпты в реальном времени.

Нужно одним батч-прогоном (офлайн) разметить исторические промпты моделью **Jev** по таксономии S01–S20 и получить таблицу разметки и аналитику по ней.

## Цель

1. Каждому историческому промпту присвоены бакеты S01–S20 (или NONE) с уверенностью и обоснованием.
2. Качество разметки проверено на выборке, размеченной людьми (T&S).
3. Сводный отчёт: распределение бакетов во времени, по креаторам, по моделям/модальностям генерации.
4. Список промптов и креаторов из красных бакетов передан в T&S для разбора.

## Правила разметки (входят в инструкцию для Jev)

- **Multi-label.** Промпт может попасть в несколько бакетов (например, S05 + S19) — модель возвращает все. Дополнительно поле `primary_code` — самый строгий из сработавших (🔴 > 🟠 > 🟡 > 🟢 > NONE).
- **Признаки несовершеннолетия в приоритете.** Сигналы детского возраста в сексуальном контексте относят промпт к S15–S18/S20 независимо от оговорок «ей 18», «на самом деле ей 1000 лет» или подписи «18+» (последнее — прямо S18).
- **Стиль ≠ возраст.** Аниме/мультстиль сам по себе не делает персонажа несовершеннолетним (S08), решают признаки возраста. При неоднозначности — флаг `needs_review`.
- **S19** — только если взрослость участника однозначно следует из промпта; иначе — красные бакеты.
- **S14** — сексуальный контент с реальным узнаваемым человеком (имя, референс-фото реального лица, «как моя бывшая») без подтверждённого согласия.
- **S01 vs S02** — нагота без сексуализации (анатомия, искусство, медицина) против акцента на эротике.
- **Обходы:** многоязычность, транслит, leetspeak, эвфемизмы, запрос, разбитый между prompt и negative prompt. Словарь известных кодовых слов предоставляет T&S.
- **Неуверенность:** если уверенность ниже порога — `needs_review = true`, промпт попадает в выборку на ручную проверку.

## Входные данные

- **Источник:** таблица логов генераций (уточнить: БД/DWH, название таблицы, владелец).
- **Период:** вся история / с даты `___` (уточнить).
- **Поля:** `prompt_id`, `creator_id`, `created_at`, `prompt`, `negative_prompt`, `modality`, `generation_model`, `style`/LoRA/character, флаг наличия референс-изображения реального человека.
- **Предобработка:**
  - дедупликация по нормализованному тексту промпта (размечаем уникальные тексты, затем джойним обратно) — сильно сокращает объём и стоимость;
  - описание персонажа/LoRA подставляется в контекст (возраст персонажа часто задан там, а не в промпте);
  - пустые/служебные промпты отфильтровываются.

## Выходные данные

Таблица `prompt_labels` (в том же DWH):

| Поле | Описание |
|---|---|
| `prompt_id` / `prompt_hash` | ключ |
| `labels` | массив `{code, confidence, evidence}`, `evidence` — фрагмент промпта, на основании которого принято решение |
| `primary_code` | самый строгий бакет |
| `severity` | green / yellow / orange / red |
| `needs_review` | true при низкой уверенности |
| `model_version`, `policy_version`, `labeled_at` | для воспроизводимости и перепрогонов |

## Этапы

1. **Выгрузка и дедуп.** Оценить количество уникальных промптов → оценка стоимости и времени прогона в Jev (токены, RPS-лимиты).
2. **Инструкция для Jev** — описание бакетов, правила выше, строгий JSON-формат ответа, few-shot примеры по пограничным случаям (синтетические, согласованные с T&S).
3. **Golden-выборка.** Стратифицированная выборка ~2 000 исторических промптов, размеченная двумя асессорами T&S (спорные — третьим). Стратификация по предварительной разметке Jev, чтобы редкие бакеты были представлены (минимум ~50 на бакет, где это возможно).
4. **Пилот на golden-выборке.** Per-class precision/recall, confusion matrix по пограничным парам (S01/S02, S08/S17/S18, S19/S16, S05/S11/S12, S09/S10, S03/S14), подбор порога `needs_review`. Итерации над инструкцией до прохождения критериев приёмки.
5. **Полный батч-прогон.** Ретраи при невалидном JSON и ошибках API, чекпоинты (прогон можно возобновить), логирование версии модели и инструкции.
6. **Ручная проверка:** все промпты из красных бакетов + все `needs_review` + случайная выборка 0.5–1 % остальных для контроля.
7. **Отчёт:** распределение бакетов по месяцам, по модальностям и моделям генерации; топ креаторов по доле 🔴/🟠; доля NONE; оценка ошибки разметки по контрольной выборке.

## Критерии приёмки

- Recall по красным бакетам (S11, S12, S14–S18, S20) на golden-выборке **≥ 0.95**, отдельно по группе «несовершеннолетние» (S15–S18, S20) — **≥ 0.97**.
- Precision по красным бакетам **≥ 0.8** (остальное отсеивает ручная проверка).
- Accuracy определения `severity` на golden-выборке **≥ 0.9**.
- Доля `needs_review` **≤ 5 %** от размеченных промптов.
- Ответ Jev валиден по JSON-схеме после ретраев для **100 %** промптов (иначе промпт помечается `needs_review`).
- Таблица `prompt_labels` и отчёт доступны T&S и аналитикам; прогон воспроизводим (зафиксированы версии модели, инструкции, порогов).

## Вне скоупа

- Проверка промптов в реальном времени перед генерацией (отдельная задача, будет опираться на результаты этой).
- Разметка самих сгенерированных изображений/видео.
- Санкции к аккаунтам креаторов — решение T&S по итогам отчёта.

## Риски и открытые вопросы

1. **Красные находки в исторических данных.** Если разметка найдёт промпты из S15–S18/S20 или S14, у компании могут возникнуть обязательства по отчётности (например, NCMEC / локальные регуляторы) и удалению контента. До запуска прогона согласовать с Legal процедуру и владельца.
2. **Доступ к данным.** Промпты содержат чувствительный контент: ограничить доступ к таблице, асессорам — wellbeing-процедуры при просмотре тяжёлого контента.
3. **Передача данных в Jev.** Где развёрнута модель (внутри периметра или внешний API), допустимо ли по политике данных отправлять туда промпты.
4. **S10 и S13** отмечены 🟠; во многих юрисдикциях такой контент незаконен — подтвердить уровень у T&S/Legal.
5. **S14:** есть ли у нас сигнал согласия (верификация лиц/KYC моделей), или любой реальный узнаваемый человек в сексуальном контексте = 🔴.
6. **Jev:** версия, лимиты контекста и RPS, стоимость токена — нужны для оценки бюджета прогона.

# Задача: классификация промптов креаторов по бакетам S01–S20 с помощью модели Jev

## Контекст

Креаторы на платформе генерируют контент (изображения / видео / текст / аудио) по текстовым промптам. Сейчас промпты не оцениваются по единой политике контента, поэтому:

- запрещённый контент (несовершеннолетние, NCII, сексуальное насилие) может попадать в генерацию;
- допустимый взрослый контент модерируется непоследовательно;
- у Trust & Safety нет разметки и статистики, чтобы видеть, какой контент реально генерируют.

Нужно оценивать каждый промпт моделью **Jev** и относить его к одному или нескольким бакетам таксономии S01–S20 (см. ниже), а по результату — пропускать, помечать 18+, отправлять на ручную проверку или блокировать генерацию.

## Цель

1. Сервис/пайплайн, который на вход получает промпт креатора и возвращает бакеты S01–S20 с уверенностью и обоснованием.
2. Маппинг бакетов в действие платформы (allow / 18+ / review / block).
3. Golden-датасет и офлайн-оценка качества Jev на нём; пороги, согласованные с T&S.
4. Логирование решений и метрики в проде.

## Логика классификации

- **Multi-label.** Промпт может попасть в несколько бакетов (например, S05 + S19). Модель возвращает все сработавшие бакеты.
- **Итоговое действие = самое строгое** среди сработавших бакетов (block > review > 18+ > allow).
- **Приоритет признаков несовершеннолетия.** Любые сигналы детского возраста (явный возраст < 18, школьный контекст, детские черты внешности/тела, «loli/shota», и т.п.) в сочетании с сексуальным контекстом относят промпт к S15–S18/S20 **независимо** от заявлений «ей 18», «на самом деле ей 1000 лет», «18+» в подписи (это прямо S18).
- **Различение S17/S18 и S08.** Стилизация (аниме, мультфильм) сама по себе не делает персонажа несовершеннолетним; решают признаки возраста. При неоднозначности — review, а не allow.
- **S19 vs S15–S18.** S19 — только когда участник явно взрослый и это однозначно следует из промпта, а детская роль — ролевая игра. Если взрослость не очевидна — эскалировать в красные бакеты.
- **S14 (NCII).** Срабатывает на сексуальный контент с **реальным узнаваемым человеком** (имя знаменитости/частного лица, ссылка на референс-фото реального человека, «как моя бывшая» и т.д.) без подтверждённого согласия. Требует учёта не только текста, но и метаданных референсов (см. Вход).
- **S01 vs S02.** Нагота без сексуализации (анатомия, искусство, грудное вскармливание, медицина) — S01; акцент на возбуждении/позах/эротике — S02.
- **Устойчивость к обходам:** многоязычные промпты, транслит, leetspeak, эвфемизмы, разбиение запрещённого запроса между промптом и negative prompt, кодовые слова комьюнити. Набор известных обходов поддерживается T&S отдельным словарём и подаётся в контекст Jev.
- **Неуверенность.** Если уверенность в красном бакете выше порога review, но ниже порога block — промпт уходит в ручную модерацию, генерация не запускается до решения.

## Вход

```json
{
  "prompt_id": "string",
  "creator_id": "string",
  "prompt": "string",
  "negative_prompt": "string | null",
  "language": "string | null",
  "modality": "image | video | text | audio",
  "style_hint": "photoreal | anime | 3d | ... | null",
  "reference_media": [
    {"type": "image", "is_real_person": true, "consent_verified": false}
  ],
  "character_ids": ["string"]
}
```

Описания персонажей/LoRA, на которые ссылается промпт, подставляются в контекст (возраст персонажа часто задан там, а не в самом промпте).

## Выход

```json
{
  "prompt_id": "string",
  "labels": [
    {"code": "S05", "confidence": 0.91, "evidence": "фрагмент промпта, на основании которого принято решение"},
    {"code": "S19", "confidence": 0.64, "evidence": "..."}
  ],
  "primary_code": "S19",
  "action": "allow | allow_18 | review | block",
  "escalation": false,
  "model_version": "jev-x.y",
  "policy_version": "2026-10",
  "latency_ms": 0
}
```

`escalation = true` для S15–S18, S20 — отдельная очередь T&S и юридически требуемая отчётность (согласовать с Legal).

## Объём работ

1. **Промпт/инструкция для Jev:** описание всех бакетов, правил приоритета, формата JSON-ответа; few-shot примеры по пограничным случаям (без реального запрещённого контента — синтетические описания, согласованные с T&S).
2. **Golden-датасет:** ≥ 3 000 промптов из прод-логов (обезличенных) + синтетика по редким классам; разметка двумя асессорами T&S, спорные — третьим. Минимум 100 примеров на каждый бакет, особый упор на пограничные пары: S01/S02, S08/S17/S18, S19/S16, S05/S11/S12, S09/S10, S03/S14.
3. **Офлайн-оценка:** per-class precision/recall, confusion matrix, анализ ошибок по пограничным парам; подбор порогов review/block.
4. **Интеграция:** вызов Jev до запуска генерации (pre-generation gate), таймаут и fail-closed поведение (если Jev недоступен — генерация 18+-контента не запускается).
5. **Логирование и дашборд:** распределение бакетов, доля review/block, нагрузка на модерацию, топ креаторов по красным бакетам.
6. **Петля обратной связи:** решения модераторов по review сохраняются и используются для пополнения golden-сета и пересмотра порогов.

## Критерии приёмки

- Recall по красным бакетам (S11, S12, S14–S18, S20) на golden-сете **≥ 0.98**, в т.ч. отдельно по группе «несовершеннолетние» (S15–S18, S20).
- Ложные блокировки (block на зелёных/жёлтых промптах) **≤ 2 %**.
- Macro-F1 по всем бакетам — зафиксировать baseline, целевое значение согласовать с T&S после первой итерации.
- Доля промптов в ручной review — **≤ 5 %** трафика (иначе пересмотр порогов).
- p95 latency классификации — **≤ 500 мс** (уточнить по бюджету пайплайна генерации).
- Корректная обработка промптов на RU / EN / ES / PT / DE / JA / KO (минимум), включая транслит.
- Устойчивость: на наборе известных обходов (adversarial-сет от T&S) recall по красным бакетам не ниже, чем на основном сете, более чем на 3 п.п.
- Формат ответа валиден по JSON-схеме в 100 % случаев (при невалидном ответе — retry, затем fail-closed в review).

## Вне скоупа

- Классификация уже **сгенерированного** медиа (отдельная задача: пост-генерационная проверка изображений/видео).
- Санкции к аккаунтам креаторов (strikes, баны) — отдельная задача на основе собранной статистики.
- Изменение самой политики контента.

## Открытые вопросы (к T&S / Legal)

1. Утвердить маппинг цвета → действие в таблице выше (особенно 🟠: это «review», «разрешено с ограниченной видимостью» или «запрещено, но без эскалации»?).
2. **S10 (человек + обычное животное) и S13 (некрофилия)** помечены 🟠: в ряде юрисдикций такой контент незаконен, и платёжные провайдеры/app stores обычно требуют его блокировать. Подтвердить, что это не 🔴.
3. Как получаем сигнал согласия для S14: есть ли верификация лиц на референсах и KYC моделей, или по умолчанию любой реальный узнаваемый человек = block?
4. Процедура и сроки обязательной отчётности по S15–S18/S20 (например, NCMEC / локальные регуляторы), кто владелец очереди эскалаций.
5. Срок хранения промптов и логов классификации, доступ к ним.
6. Что такое «Jev» в контексте инфраструктуры: версия модели, лимиты (контекст, RPS), есть ли возможность дообучения или только промптинг.
